# Цепочка блоков на Flask

Локальное учебное демо. Добавьте текстовый блок, проверьте связи в цепочке и вычислите доказательство работы для ожидающих блоков. Интерфейс работает без внешних ресурсов.

## Запуск

Понадобится Python 3.10 или новее. В корне проекта выполните команды в PowerShell.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Откройте [127.0.0.1:5000](http://127.0.0.1:5000/). Также можно запустить приложение командой `flask --app server run` из активированного окружения.

В macOS и Linux используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

## Что проверяет демо

Хеш SHA-256 связывает номер, время, текст и хеш предыдущего блока. Доказательство работы хранится отдельно: приложение ищет `nonce`, при котором SHA-256 строки `хеш_блока:nonce` начинается с двух нулей. Поэтому можно добыть доказательство для старого блока и сохранить его связи с потомками.

Допустимо добавить блок без доказательства. За один запрос майнинг обрабатывает до 32 ожидающих блоков. Проверка показывает сбой нумерации, нарушение ссылки, подмену содержимого и недействительное доказательство. При обнаружении ошибки запись останавливается.

В демо одна локальная база и нет внешнего эталона. Если пересчитать все хеши и доказательства после подмены или удалить хвост цепочки, локальная проверка может этого не заметить.

## Хранение и импорт

По умолчанию используется `instance/blockchain.db`. Другой файл можно указать через `BLOCKCHAIN_DB_PATH`. Данные добавляются внутри транзакции SQLite.

На первом запуске приложение проверяет старые файлы `blocks/N.json` по SHA-256 их исходных байтов и импортирует текст, порядок и время. JSON-файлы сохраняются. Старые доказательства рассчитывались по другой формуле, поэтому импортированные блоки можно обработать заново. Если проверка исходных файлов не проходит, импорт останавливается с сообщением об ошибке.
